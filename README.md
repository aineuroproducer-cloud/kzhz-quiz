# Карта сигналов 40+ — квиз и воронка под холодный трафик

Два файла:

| Файл | Что это |
|---|---|
| `index.html` | Боевой квиз. Один файл, без зависимостей. Ставится на домен как есть. |
| `voronka.html` | Прототип воронки для обсуждения в команде. На продакшен не идёт. |
| `archive/quiz-v1.html` | Первая версия квиза. Оставлена для сравнения. |

Главное отличие от первой версии: воронка больше не начинается со страницы результата.
Добавлены экран входа, микро-результат до интимных вопросов, замер маркеров на сайте,
три равных мессенджера, печать карты, embed-режим для блога и сквозная аналитика.

---

## 1. Что нужно заполнить перед запуском

Всё в одном месте — блок `CFG` в начале `<script>` в `index.html`.

```js
relay:    ''        // URL своего обработчика. Пусто = данные не уходят, квиз работает
ymId:     0         // ID Яндекс.Метрики. 0 = цели не отправляются
channels: [...]     // BOTNAME и CLUBNAME заменить на реальные адреса ботов
allowPrint: true    // тихая ссылка «забрать карту без мессенджера»
resumeDays: 7       // сколько дней хранить незаконченное прохождение
```

Дополнительно по тексту:

- **Регалии НК.** Два места помечены жёлтым маркером в вёрстке и атрибутом `data-ph="regalia"`:
  в шапке страницы и в блоке доверия на экране входа. Нужны специализация, стаж и один-два
  факта практики. Без обещаний результата — только кто она и чем занимается.
  Это самый важный незаполненный элемент: на холодном трафике в медицинской теме
  доверие к человеку решает больше, чем любой текст воронки.
- **Профили A и C.** Тексты написаны и работают, но вычитаны менее тщательно, чем профиль B
  («Опора и комфорт»). До платного трафика их стоит прогнать через НК.

### Проверка экранов для медицинской вычитки

НК не нужно проходить тест девять раз. Ссылки открывают конкретный экран сразу:

```
index.html?preview=b-normal     результат, профиль «Опора и комфорт»
index.html?preview=b-caution    то же, осторожная редакция
index.html?preview=a-normal     профиль «Переход и ресурс»
index.html?preview=a-caution    то же, осторожная редакция
index.html?preview=c-normal     профиль «Система и движение»
index.html?preview=stop         стоп-экран, ответ «да»
index.html?preview=unsure       стоп-экран, ответ «не уверена»
index.html?preview=micro        микро-результат
```

Режим предпросмотра ничего не отправляет в аналитику и в релей.

## 2. Релей: почему нельзя писать в SalesBot и GetCourse напрямую

Страница квиза публичная. Любой ключ, положенный в неё, виден через «Посмотреть код» —
и API-ключ SalesBot или секрет GetCourse дают доступ к базе клиентов. Поэтому квиз
отправляет данные на **свой тонкий обработчик** (n8n, Make, Apps Script, любой серверный
скрипт), а тот уже вызывает SalesBot и GetCourse со своей стороны, где ключи не видны.

Второй, менее очевидный повод: **на момент прохождения теста контакта ещё нет.**
Контакт появляется только когда женщина заходит в бота. Значит, релей должен уметь
хранить анонимные прохождения по `session` и доклеивать к ним лид позже.

```
Квиз ──POST JSON──> ваш релей ──> SalesBot (переменные клиента)
   (без ключей)                └─> GetCourse (сделка/пользователь)
                               └─> лог анонимных прохождений
```

### Формат запроса

`POST <relay>`, `Content-Type: application/json`. Отправляется через `sendBeacon`,
то есть **ответ не читается** — релей может отвечать чем угодно, главное не ошибкой CORS.

```json
{
  "session": "a7k2m9",
  "event": "complete",
  "ts": 1771200000,
  "source": {
    "src": "vk", "medium": "cpc", "campaign": "pelvic_kegel_01",
    "content": "", "term": "",
    "topic": "pelvic", "article": "tazovoe-dno-posle-40",
    "embed": 0, "ref": "https://...", "landing": "https://..."
  },
  "answers": {
    "AGE_STAGE": "46–55",
    "PRIMARY": "Тазовое дно и мочеиспускание",
    "SIGNAL": ["Мочеиспускание и таз", "Сон"],
    "IMPACT": "Регулярно мешает",
    "SYSTEM_NEED": "Иногда",
    "INTENT": "Получить короткую практику",
    "LIMITS": ["Ограничений нет"],
    "SAFETY": "Нет",
    "DESIRED": "Меньше ограничений из-за таза"
  },
  "markers": { "m1": 0, "m2": 1, "m3": 0 },
  "derived": { "profile": "B", "edition": "normal", "safety": 0, "answered": 9, "of": 9 }
}
```

Значения `event`:

| event | Когда |
|---|---|
| `view` | страница открыта |
| `partial` | ответ на каждый вопрос — по этим записям видно, где отвал |
| `micro` | показан микро-результат |
| `complete` | дошла до результата |
| `markers` | сделала замер трёх маркеров |
| `cta` | нажала кнопку мессенджера (в `meta.channel` — какого) |
| `print` | забрала карту без мессенджера |
| `safety_stop` | стоп-ветка |

Одна и та же `session` приходит много раз. Релей делает **upsert по session**, а не insert,
иначе на каждое прохождение будет десяток строк.

Персональных данных квиз не передаёт: ни имени, ни телефона, ни почты. Их просто нет —
контакт появляется уже в мессенджере.

### Склейка с ботом

Ссылка в мессенджер содержит `payload` из 17 символов, алфавит `[0-9a-z]`:

```
v2 b n 0 1 2 1 0 1 2 a7k2m9
│  │ │ │ │ │ │ └┬┘   └──┬──┘
│  │ │ │ │ │ │  │       └ session — ключ склейки с данными квиза
│  │ │ │ │ │ │  └ три маркера (0/1/2, 9 = не отмечен)
│  │ │ │ │ │ └ INTENT
│  │ │ │ │ └ IMPACT
│  │ │ │ └ AGE_STAGE
│  │ │ └ стоп-сигнал: 0 или 1
│  │ └ редакция: n обычная, c осторожная
│  └ профиль: a, b или c
└ версия схемы
```

Длина выбрана под самый узкий лимит из трёх мессенджеров: Telegram — 64 символа,
MAX — 128, у VK лимит `ref` в документации не зафиксирован, проверить на боевом боте.
Профиль и редакция лежат в payload отдельно от session намеренно: бот может выдать
правильную карту сразу, даже если релей в этот момент недоступен.

В боте: взять `start` / `ref`, отрезать последние 6 символов — это `session`,
по нему забрать у релея полные ответы и замер маркеров.

### SalesBot

Релей вызывает метод записи переменных клиента и передаёт `profile`, `edition`,
`safety`, `mk1..mk3`, `session`, `src`, `topic`. Дальше сценарий бота ветвится по
`edition` и `safety`, а на дне 14 читает `mk1..mk3` и показывает их женщине обратно.

Точные URL и имена методов брать из актуальной документации SalesBot — они менялись.

### GetCourse

Создание сделки или пользователя: `POST https://<аккаунт>.getcourse.ru/pl/api/deals`
с `action=add`, `key=<секрет>`, `params=base64(json)`. Ответы квиза удобно положить
в дополнительные поля сделки, `session` — в поле, по которому потом ищется склейка.
Формат подтвердить по документации вашего аккаунта.

**Что считать источником истины.** Если и SalesBot, и GetCourse получают одни и те же
данные, они разъедутся. Решите заранее: контакт и переписка живут в SalesBot, деньги и
сделки — в GetCourse, а анонимные прохождения — только в релее. Квиз пишет во все три,
но менять запись после создания должен кто-то один.

## 3. Встройка в блог

Блог — главный источник холодного трафика, который не надо покупать. Квиз встраивается
в статью два раза: после первого смыслового блока, пока интерес на пике, и в конце для
дочитавших.

```html
<iframe src="/quiz/index.html?embed=1&topic=pelvic&article=tazovoe-dno-posle-40&src=blog"
        style="width:100%;border:0;display:block" height="620"
        title="Тест: карта сигналов 40+"></iframe>

<script>
window.addEventListener('message', function(e){
  if(e.data && e.data.type === 'kzhz-quiz-height'){
    var f = document.querySelector('iframe[src*="quiz"]');
    if(f) f.style.height = (e.data.height + 24) + 'px';
  }
});
</script>
```

`embed=1` убирает шапку страницы, SEO-блок и фон — остаётся только карточка квиза,
а высота подгоняется под содержимое автоматически.

### Параметр `topic`

Предзаполняет второй вопрос и меняет текст экрана входа на вариант для органики.
Ставится по теме статьи:

| `topic` | Статья про |
|---|---|
| `pelvic` | тазовое дно, мочеиспускание |
| `cycle` | приливы, цикл |
| `sleep` | сон, энергия |
| `intimacy` | интимный комфорт |
| `motion` | движение, суставы |
| `system` | как собрать всё в систему |

Важно: вопрос только **предотмечен**, женщина его подтверждает. Молча подставлять
ответ за человека в медицинской теме нельзя — она могла прийти на статью за кого-то другого.

### SEO

На самой странице квиза (не в embed) есть статический текстовый блок: он в DOM всегда,
видим на экране входа и прячется, когда начинается прохождение. Страница может
ранжироваться сама по запросам вида «тест менопауза», «с чего начать после 40».
Заголовок, description и og-теги заполнены — проверьте, что домен и og:image подставлены.

## 4. Аналитика

Все события уже отправляются кодом. Нужно только создать цели **с теми же именами**
в Метрике и подставить `ymId`. Дополнительно события уходят в `gtag` и `dataLayer`,
если они на странице есть.

### Три числа, которые решают всё остальное

| № | Воронка | События |
|---|---|---|
| 1 | открыла страницу → начала тест | `quiz_view` → `quiz_start` |
| 2 | начала → дошла до результата | `quiz_start` → `quiz_complete` |
| 3 | результат → ушла в мессенджер | `quiz_complete` → `quiz_cta_*` |

Пока эти три числа не измерены, спорить про тексты прогрева, цены и состав продукта
бессмысленно: неизвестно, доходит ли до них кто-нибудь.

### Полный список целей

```
quiz_view         открыта страница
quiz_start        нажала «Начать»
quiz_q_view       показан вопрос         (параметр q — какой)
quiz_q_answer     ответила на вопрос     (параметр q — какой)
quiz_micro        показан микро-результат
quiz_deep_start   пошла в уточняющую часть
quiz_early_exit   выбрала «мне пока хватит»
quiz_complete     дошла до результата    (параметры profile, edition)
quiz_markers      сделала замер маркеров
quiz_cta_tg       ушла в Telegram
quiz_cta_vk       ушла во ВКонтакте
quiz_cta_max      ушла в MAX
quiz_print        забрала карту без мессенджера
quiz_safety_stop  попала в стоп-ветку
quiz_resume       вернулась к незаконченному
```

В каждом событии приходят параметры `src`, `topic`, `embed` — поэтому органику и
платный трафик можно сравнивать в одном отчёте. Это бесплатный A/B на входе:
один и тот же квиз на двух источниках. Если у органики число №1 заметно выше, значит
проблема платного трафика в креативе, а не в квизе.

Отдельно стоит смотреть `quiz_safety_stop / quiz_complete`. Это не конверсия, а
**качество входящего трафика**: если доля стоп-ответов высокая, реклама приводит женщин,
которым нужен врач, а не практикум. Это сигнал таргетологу, а не копирайтеру.

## 5. Два решения, которые остаются за владельцем

**Тихая ссылка «забрать карту без мессенджера».** Она снимает часть контактов — и при
этом снимает страх «сейчас втянут в рассылку», который мешает и тем, кто в бота в итоге
заходит. Если её убрать, этот сегмент исчезнет полностью, и вы не узнаете, сколько его
было. Порог доли `quiz_print`, после которого решение пересматривается, стоит назвать
заранее: иначе спор будет про вкусы, а не про цифру. Выключается флагом `allowPrint`.

**Автопереход после выбора ответа.** Одиночные вопросы перелистываются сами через
170 мс — это убирает лишний тап на каждом из девяти шагов. Обратная сторона: при
случайном касании женщина уезжает на следующий вопрос. Кнопка «Назад» есть на каждом
шаге, но для аудитории 46–65 это осознанный компромисс в пользу скорости. Если по
`quiz_q_answer` будет видно много возвратов назад — убрать `setTimeout` в `buildOpts`.

## 6. Чего в этих файлах нет

Квиз и его аналитика готовы. Не существует пока:

- рекламы и креативов;
- самого бота и его сценария — payload и контракт релея описаны, сценарий нет;
- голосового сообщения от НК на день 0;
- продукта на день 7 с ценой — в прототипе он стоит как «короткая встреча / скрининг»,
  потому что это единственный оффер, который не противоречит карте: карта сама говорит,
  что без осмотра тактику подобрать нельзя;
- решения, есть ли в воронке личный разбор и в каком формате.

Всё это помечено в `voronka.html` жёлтой меткой «гипотеза». Зелёной — то, что уже работает в коде.
