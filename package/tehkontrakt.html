Техконтракт внедрения

Что заполнить перед запуском, куда квиз отправляет данные и почему не напрямую в SalesBot, как встроить тест в статьи блога и какие цели создать в Метрике.

1. Что заполнить перед запуском

Всё в одном месте: блок CFG в начале скрипта в index.html.

relay:      ''      // URL своего обработчика. Пусто = данные не уходят, квиз работает
ymId:       0       // ID Яндекс.Метрики. 0 = цели не отправляются
channels:   [...]   // BOTNAME и CLUBNAME заменить на реальные адреса ботов
allowPrint: true    // тихая ссылка «забрать карту без мессенджера»
resumeDays: 7       // сколько дней хранить незаконченное прохождение

Регалии проставлены по справке об эксперте и заглушками больше не являются: Наталья Константиновна Бутолина, врач-педиатр, врач ЛФК, реабилитолог, практический врачебный опыт с 1997 года, главный врач оздоровительного центра «Фомальгаут +» в Самаре. В коротком блоке доверия на экране входа ведущей названа специальность, относящаяся к делу — врач ЛФК и реабилитолог. Если нужно вывести полный перечень, он добавляется там же.

Проверка экранов для медицинской вычитки

Проходить тест девять раз не нужно, каждая ссылка открывает конкретный экран сразу:

СсылкаЭкран
?preview=b-normalРезультат, профиль «Опора и комфорт»
?preview=b-cautionТо же, осторожная редакция
?preview=a-normalПрофиль «Переход и ресурс»

Режим предпросмотра ничего не отправляет ни в аналитику, ни в релей.

2. Релей: почему не напрямую в SalesBot и GetCourse

Страница квиза публичная. Любой ключ, положенный в неё, виден через «посмотреть код», а API-ключ SalesBot или секрет GetCourse дают доступ к базе клиентов. Поэтому квиз отправляет данные на свой тонкий обработчик (n8n, Make, Apps Script, любой серверный скрипт), а тот уже вызывает SalesBot и GetCourse со своей стороны.

Второй повод менее очевиден: на момент прохождения теста контакта ещё нет. Он появляется только когда женщина заходит в бота. Значит, релей должен уметь хранить анонимные прохождения по session и доклеивать к ним лид позже.

Квиз ──POST JSON──> ваш релей ──> SalesBot (переменные клиента) (без ключей) └─> GetCourse (сделка / пользователь) └─> лог анонимных прохождений

Формат запроса

POST <relay>, Content-Type: application/json. Отправка идёт через sendBeacon, то есть ответ не читается: релей может отвечать чем угодно, главное — не ошибкой CORS.

eventКогда приходит

Upsert, а не insert

Одна и та же session приходит много раз. Если релей будет делать insert, на каждое прохождение получится десяток строк.

Персональных данных квиз не передаёт: ни имени, ни телефона, ни почты. Их просто нет, контакт появляется уже в мессенджере.

Склейка с ботом

Ссылка в мессенджер содержит payload из 17 символов, алфавит [0-9a-z]:

v2 b n 0 1 2 1 0 1 2 a7k2m9 │ │ │ │ │ │ │ └─┬──┘ └──┬──┘ │ │ │ │ │ │ │ │ └ session, ключ склейки с данными квиза │ │ │ │ │ │ │ └ три маркера: 0 / 1 / 2, девятка = не отмечен │ │ │ │ │ │ └ INTENT │ │ │ │ │ └ IMPACT │ │ │ │ └ AGE_STAGE │ │ │ └ стоп-сигнал: 0 или 1 │ │ └ редакция: n обычная, c осторожная │ └ профиль: a, b или c └ версия схемы

Длина выбрана под самый узкий лимит из трёх мессенджеров: Telegram — 64 символа, MAX — 128, у VK лимит ref в документации не зафиксирован, проверить на боевом боте.

Профиль и редакция лежат в payload отдельно от session намеренно: бот выдаёт правильную карту сразу, даже если релей в этот момент недоступен.

В боте: взять start или ref, отрезать последние 6 символов — это session, по нему забрать у релея полные ответы и замер маркеров.

SalesBot

Релей вызывает метод записи переменных клиента и передаёт profile, edition, safety, mk1..mk3, session, src, topic. Сценарий бота ветвится по edition и safety, а на дне 14 читает mk1..mk3 и показывает их женщине обратно. Точные URL и имена методов брать из актуальной документации SalesBot, они менялись.

GetCourse

Создание сделки или пользователя: POST https://<аккаунт>.getcourse.ru/pl/api/deals с action=add, key=<секрет>, params=base64(json). Ответы квиза удобно положить в дополнительные поля сделки, session — в поле, по которому потом ищется склейка. Формат подтвердить по документации вашего аккаунта.

Что считать источником истины

Если и SalesBot, и GetCourse получают одни и те же данные, они разъедутся. Решить заранее: контакт и переписка живут в SalesBot, деньги и сделки в GetCourse, анонимные прохождения только в релее. Квиз пишет во все три, но менять запись после создания должен кто-то один.

3. Встройка в блог

Блог — главный источник холодного трафика, который не надо покупать. Квиз встраивается в статью дважды: после первого смыслового блока, пока интерес на пике, и в конце для дочитавших.

<iframe src="/quiz/index.html?embed=1&topic=pelvic&article=tazovoe-dno-posle-40&src=blog"
        style="width:100%;border:0;display:block" height="620"
        title="Тест: карта сигналов 40+"></iframe>

<script>
window.addEventListener('message', function(e){
  if(e.data && e.data.type === 'kzhz-quiz-height'){
    var f = document.querySelector('iframe[src*="quiz"]');
    if(f) f.style.height = (e.data.height + 24) + 'px';
  }
});
</script>

embed=1 убирает шапку страницы, SEO-блок и фон, остаётся только карточка квиза, а высота подгоняется под содержимое автоматически.

Параметр topic

Предзаполняет второй вопрос и переключает экран входа на вариант для органики.

topicСтатья про
pelvicТазовое дно, мочеиспускание
cycleПриливы, цикл
sleepСон, энергия
intimacyИнтимный комфорт
motionДвижение, суставы
systemКак собрать всё в систему
Ответ предотмечен, но не подставлен

Женщина подтверждает его сама. Молча отвечать за человека в медицинской теме нельзя: она могла прийти на статью за кого-то другого.

SEO

На странице квиза (не в embed) есть статический текстовый блок: он в DOM всегда, виден на экране входа и прячется, когда начинается прохождение. Страница может ранжироваться сама по запросам вида «тест менопауза», «с чего начать после 40». Заголовок, description и og-теги заполнены, проверить подстановку домена и og:image.

4. Аналитика

Все события уже отправляются кодом. Нужно создать цели с теми же именами в Метрике и подставить ymId. Дополнительно события уходят в gtag и dataLayer, если они на странице есть.

quiz_view         открыта страница
quiz_start        нажала «Начать»
quiz_q_view       показан вопрос          (параметр q)
quiz_q_answer     ответила на вопрос      (параметр q)
quiz_micro        показан микро-результат
quiz_deep_start   пошла в уточняющую часть
quiz_early_exit   выбрала «мне пока хватит»
quiz_complete     дошла до результата     (profile, edition)
quiz_markers      сделала замер маркеров
quiz_cta_tg       ушла в Telegram
quiz_cta_vk       ушла во ВКонтакте
quiz_cta_max      ушла в MAX
quiz_print        забрала карту без мессенджера
quiz_safety_stop  попала в стоп-ветку
quiz_resume       вернулась к незаконченному

В каждом событии приходят src, topic, embed, поэтому органику и платный трафик можно сравнивать в одном отчёте.

Отдельно стоит смотреть quiz_safety_stop / quiz_complete. Это не конверсия, а качество входящего трафика: высокая доля означает, что реклама приводит женщин, которым нужен врач, а не практикум.

5. Два решения, которые остаются за владельцем

Тихая ссылка «забрать карту без мессенджера»

Она снимает часть контактов и одновременно снимает страх «сейчас втянут в рассылку», который мешает и тем, кто в бота в итоге заходит. Если её убрать, сегмент исчезнет полностью, и останется неизвестным, сколько его было. Порог доли quiz_print, после которого решение пересматривается, стоит назвать заранее. Выключается флагом allowPrint.

Автопереход после выбора ответа

Одиночные вопросы перелистываются сами через 170 мс, это убирает лишний тап на каждом из девяти шагов. Обратная сторона: при случайном касании женщина уезжает на следующий вопрос. Кнопка «Назад» есть на каждом шаге. Для аудитории 46–65 это осознанный компромисс в пользу скорости. Если по quiz_q_answer будет видно много возвратов назад, убрать setTimeout в buildOpts.
